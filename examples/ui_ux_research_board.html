🎨 Visual Languages Beyond Cards: Main Synth Pages vs. Modular FX/Mod

The Core Principle: Visual form follows functional reality. The sound engine is fixed; FX and modulations are reconfigurable.

PARADIGM SPLIT
🎛️ Main Synthesis Pages (Voice 1, Voice 2, Transients, Output)

Functional Reality: The signal path is fixed and directional. An oscillator feeds a filter, which feeds an amplifier. It is NOT drag-and-drop.

Why Cards Fail Here: Forcing fixed signal paths into isolated, floating rectangular cards makes the instrument feel like an unsorted box of spare parts rather than an acoustic engine.

→ Solution: Unified Sculpted Console / Milled Instrument Chassis
🧩 FX Rack & Modulation Dock (Pre/Post FX, Mod Matrix, Strip)

Functional Reality: The signal path is dynamic, reconfigurable, and arbitrary. Slots can be reordered; mod sources are patched via cables.

Why Cards Excel Here: Cards, tiles, and pedal boxes are the ideal physical metaphor because musicians intuitively understand dragging, swapping, and patching separate units.

→ Solution: Keep Modular Drag-and-Drop Eurorack Cards & Tiles!

Industry Research: The Unconsidered

Evaluating highly successful UI paradigms from plugins outside the standard wavetable synth sphere.

Valhalla DSP Typography-First Minimalism

  • The Paradigm: Valhalla completely rejects 3D rendered knobs and skeuomorphism. Their plugins are purely 2D vector shapes with massive, highly readable typography.
  • The Lesson: Don't force users to squint at a tiny number below a photorealistic knob. We should prioritize huge font readouts that temporarily replace the knob graphic while it's being turned.

Output (Portal / Thermal) The Giant Macro

  • The Paradigm: While they have deep sub-menus, the entire UI is dominated by a massive, central X/Y macro pad that controls dozens of parameters simultaneously.
  • The Lesson: The Klang Suite needs a dedicated "Performance Page" where the 4 hardware encoders are mapped to massive, central Macros (e.g., TENSION, WASH, CHAOS, DRIVE) rather than granular DSP values.

Elektron Overbridge Hardware-to-VST

  • The Paradigm: Elektron creates hardware grooveboxes (Digitakt), but their Overbridge VST maps that hardware perfectly to a screen.
  • The Lesson: They use Parameter Locks. If we hold a step on the TBD-16's 16-button grid, the 4 screen knobs should temporarily glow red. Any changes made are locked *only* to that sequencer step. This gives us per-step automation without a DAW!

FabFilter (Pro-Q 3 / Volcano) Contextual Hover UX

  • The Paradigm: There are no static knobs. UI elements only appear when you hover over the exact node or frequency band you want to edit.
  • The Conflict: This is amazing for mice, but terrible for hardware encoders which require static, predictable mappings.
  • The Compromise: We keep static knobs for the encoders, but use FabFilter's philosophy for the Visualizers. Spectrograms and waveforms should sit *behind* the knobs to maximize screen real estate.

Advanced UX & Accessibility (A11y)

Pushing the boundaries of interface design beyond just making it look "cool".

Shape-Based Modulation (Colorblind Safe)

  • The Problem: Relying purely on color (Green for LFO, Red for Envelope) completely locks out colorblind users from quickly reading the Mod Matrix.
  • The Paradigm: We couple color with distinct geometry. LFO modulation rings are dashed/dotted lines. Envelope modulation rings are solid bars. Macro modulation uses small triangular tick marks.

  • The Paradigm: Standard "Undo" is linear. Sound design is non-linear. We provide 4 quick-save "Snapshot" slots in the header.
  • The Twist: You don't just click between them. An X/Y pad allows you to morph parameter values between all four snapshots simultaneously to discover happy accidents.

The Patch Browser & Tagging

Oversampling & Anti-Aliasing

Polyphase Half-Band Filters

We solved oscillator aliasing with MIP mapping, but what about non-linear distortion (Drive/Wavefolding)?

  • The Problem: Passing a high note through a wavefolder generates harmonics that instantly wrap around Nyquist and ruin the sound.
  • The Solution: 2x or 4x Oversampling inside the distortion module.
  • The Math: We use Polyphase IIR or FIR Half-Band filters to upsample, run the `tanh()` drive, and downsample. These specific filters are mathematically optimized to drop 50% of the calculations (since half the coefficients are zero), saving massive CPU on the ESP32-P4.

Casio CZ Phase Distortion

A Cheaper Alternative to FM

  • The Concept: True Frequency Modulation (Yamaha DX7) requires calculating multiple sine waves interacting. Casio's Phase Distortion (PD) only uses a single sine wave, but warps the *read pointer* (the phase) to create jagged saws and resonant squares.
  • Hardware Win: PD requires virtually zero CPU because it's just basic linear interpolation on the phase accumulator. Perfect for 16-voice polyphony on an embedded chip!

Analog RC Envelope Modeling

The Physics of "Punch"

  • The Problem: Standard digital ADSRs use linear math. They sound "clicky" and lifeless.
  • The Concept: Real analog synths use capacitors that charge and discharge. This creates exponential curves that approach targets but never mathematically reach zero.
  • The DSP: We use a 1-pole recursive lowpass filter on a step signal. The "Punch" comes from tuning the Attack to be slightly convex and the Decay to be strictly exponential.

Microtonality (MTS-ESP)

Breaking 12-TET

  • The Concept: The standard `440.0 * pow(2.0, (note - 69) / 12.0)` locks the synth into Western 12-tone equal temperament.
  • The Standard: Implementing ODDSound's MTS-ESP API allows the synth to instantly receive non-Western scales (Arabic maqams, Just Intonation) directly from the DAW or master tuning plugins.
  • Hardware Mapping: The TBD-16 sequencer will need a visual way to represent notes that fall "between" the standard piano keys.

The Rock Solid Core

Ensuring absolute stability across desktop (macOS/Windows) and embedded targets (ToadTracker/TBD-16).

Memory & Concurrency Locked Down

  • No Runtime Allocation: `prepareToPlay()` allocates all voices and delay lines. Zero `new` or `malloc` in the audio thread.
  • SPSC Queues: 100% lock-free parameter updates. The UI pushes 32-bit float atomic changes to the audio thread via a ring buffer to prevent denormal/NaN bursts.
  • FastMath.h: All standard CRT transcendentals (`sin`, `pow`, `tanh`) are replaced with polynomial approximations. Mandatory for the ESP32-P4 (400MHz).

Wavetable Architecture

Anti-Aliasing Strategies (MIP Mapping)

Playing a wavetable at high pitches causes brutal digital aliasing if the harmonics exceed the Nyquist frequency (24kHz at 48kHz sample rate).

  • The Solution: MIP-mapped tables. When a user imports a WAV, we generate 10 versions of the table, progressively filtering out high harmonics. The oscillator interpolates between tables based on the pitch.
  • Hardware Limit: MIP-mapped tables consume RAM. On desktop, this is negligible. On TBD-16 (PSRAM), we may need to dynamically downsample to 8-bit.

Alpha Juno (The Hoover Engine)

The Roland Alpha Juno is famous for its unique oscillator states that combine pulse-width modulation (PWM) with sawtooth waves.

DSP Implementation

  • Base Phasor: A single, high-resolution, band-limited phasor (BLIT or PolyBLEP) running at audio rate.
  • Saw-PWM: We take the saw wave and subtract a phase-shifted version of itself to create the iconic Juno "PWM Saw".
  • Sub-Oscillator: A cheap divide-by-2 counter on the phasor frequency generates a perfect square wave one octave down. Requires near-zero CPU.

West-Coast Chaos & Drive

Adding more esoteric synthesis methods that fit easily into the 4-control Mega Modules.

Buchla-Style Wavefolding

  • The Math: Instead of clipping a signal when it exceeds 1.0 (like Tanh), a wavefolder uses `sin()` to wrap the signal back down, creating intensely complex harmonics.
  • The Code: `y = sin(x * fold_depth) * symmetry_offset;` (Using FastMath, this is incredibly cheap!).

Karplus-Strong (Bonus Idea!)

  • Concept: Physical modeling of strings and membranes.
  • The Math: Excite a short delay line with a burst of white noise, and feed it back through a simple low-pass filter. The delay time determines the pitch.
  • Hardware Advantage: Karplus-Strong is famously one of the most CPU-efficient ways to synthesize realistic plucks. Perfect for embedded hardware!

Advanced Filter DSP

Zero-Delay Feedback (ZDF)

Standard digital filters "cramp" near the Nyquist frequency and suffer from 1-sample delays in the feedback loop, destroying the analog sound.

  • The Topology: We use Topology-Preserving Transform (TPT) filters evaluated via the Trapezoidal Rule.
  • Non-Linearity: To emulate Moog ladders and MS-20 screamers, we inject a non-linear saturation `tanh()` directly into the feedback path.
  • Hardware Optimization: A true `tanh()` is too slow for the ESP32-P4. We use our `FastMath::pade_tanh()` to retain the aggressive saturation at a fraction of the CPU cost.

The "Direct-to-Sample" Pipeline

Offline WAV rendering directly inside the plugin thread.

The Offline Renderer

  • The Threat: Calling `processBlock` offline on the UI thread will freeze the DAW. Calling it on the Audio Thread will cause a dropout.
  • The Architecture: We spin up a low-priority background thread specifically for offline rendering. It allocates its own standalone instance of the DSP graph, disconnected from the audio outputs.
  • The Output: It rapidly calculates audio (usually taking < 100ms), writes to a `.wav` file in the system Temp folder using `juce::WavAudioFormat`.
  • The UX Handoff: A `juce::DragAndDropContainer` is exposed to the UI. The user clicks a "WAV" icon and drags it directly into Ableton/Logic's arrangement view.

Edge ML Saturation (RTNeural)

Can we use Machine Learning on the embedded hardware instead of algorithmic DSP?

Neural Net VSTs on ESP32-P4

  • The Concept: Instead of writing complex C++ to emulate a Moog ladder filter, we train a tiny Long Short-Term Memory (LSTM) neural network on real analog hardware and run the model inference live.

Modal Resonators (Physical Modeling)

Turning acoustic physics into a synth module.

Synthesizing Glass, Metal, and Strings

  • The Concept: Inspired by Mutable Instruments *Rings*. Instead of a standard oscillator, we shoot a tiny click of white noise into a bank of 64 highly-tuned bandpass filters.
  • The Sound: It rings out like a struck bell, a plucked string, or a blown tube.
  • The 4 Knobs: [STRUCTURE] (inharmonicity), [BRIGHTNESS] (filter cutoff), [DAMPING] (decay time), and [POSITION] (where the virtual object is struck).
  • Why it fits: It distills insanely complex physical modeling mathematics into 4 highly tactile, fun parameters that guarantee a "sweet spot" anywhere you turn them.

Binaural HRTF Panning

Beyond stereo widening.

True 3D Spatial Audio

  • The Concept: Instead of panning left/right by changing volume, we use Head-Related Transfer Functions (HRTFs) to filter the audio based on how human ears perceive sounds in 3D space.
  • The Result: Sounds appear to physically rotate *around* the listener's head, above them, and behind them (requires headphones).
  • The Implementation: A Mega-FX card where the knobs control Azimuth, Elevation, Distance, and Room Size.

Granular Cloud Synthesis

Particle Audio

  • The Concept: Slicing audio samples into 10-millisecond "grains" and spraying them across the stereo field like mist.
  • The 4 Knobs: [POSITION] (where to read the sample), [DENSITY] (how many grains per second), [SIZE] (length of each grain), and [SPRAY] (random pitch/pan jitter).
  • The Processing Cost: Extreme. Requires tracking 50-100 micro-voices per actual note. Would definitely require the "Mono with Tails" architecture to even stand a chance on the ESP32-P4.

Cellular Automata Sequencing

Conway's Game of Life for MIDI

  • The Concept: A generative sequencer based on cellular biology. A grid of "cells" lives, dies, or spawns based on how many neighbors it has.
  • The Music: As the grid evolves on screen, cells that hit the edges of the grid trigger MIDI notes. The result is constantly evolving, organic rhythms that never truly repeat.
  • Visual Output: The 240x240 OLED screen on the TBD-16 would just render the Game of Life pixels simulating in real-time.

Local ML Macro Suggester

Utilizing local machine learning in the standalone editor to auto-map complex presets.

The "Smart Map" Feature

  • Parses the synthesizer's underlying preset schema and DSP graph.
  • Uses a local, lightweight neural net (not cloud AI) to suggest the 8 best macroscopic controls.
  • Saves CPU by running exclusively in the Standalone Editor, totally bypassed in the DAW VST.

TKS DSP Integration (Blue Sky)

Porting The Klang Suite to TBD-16

  • The Challenge: The ESP32-P4 is powerful (400MHz, SIMD), but standard C++ JUCE plugins will not cross-compile cleanly to bare-metal embedded ESP-IDF environments.
  • The Solution: We must aggressively decouple the TKS `processBlock` and `TbdAudio::FastMath` into a pure, headless `C++20` static library. No `juce::String`, no `juce::AudioBuffer`, just raw float arrays.
  • Polyphony: As previously established, strict "Mono-with-Tails" voice allocation is mandatory here to keep the ESP32-P4 from stalling during heavy modulation.

ToadTracker Synergy (Blue Sky)

How the TBD-16 interacts with ToadTracker workflows.

Headless Sequencing & Parameter Locks

  • The UX Paradigm: ToadTracker can sequence TKS parameters via MIDI CC. But on the hardware, the RP2350B intercepts encoder turns while a step is held.
  • Visual Feedback: When a user parameter-locks a TKS knob on the TBD-16 hardware, ToadTracker's UI on the desktop should instantly highlight that step value in the tracker grid (e.g., column `04 6A`).
  • The Groovebox Workflow: The TBD-16 can run 16 tracks. If we use TKS as the sound engine for Track 1, the RP2350B just sends rapid-fire struct updates via SPI to the ESP32-P4 to update the synth parameters per-step.

Wireless Patch Sync (ESP32-C6)

The Connected Synth

  • The Hardware: The dadamachines TBD-16 has a dedicated ESP32-C6 chip for WiFi and Bluetooth.
  • The Workflow: No USB cables required to load presets. When you hit "Save" on The Klang Suite desktop VST, the JSON parameter payload is silently broadcast over the local UDP network.
  • Instant Hardware Update: If the TBD-16 is on the same WiFi network, it catches the UDP packet, updates its PSRAM, and instantly plays the new sound. Designing sounds on the PC while playing them on the hardware becomes entirely seamless.
